### 1. 中文字形根因修复（UiFont.cs）
- 问题：`Font.CreateDynamicFontFromOSFont("Microsoft YaHei")` 因 YaHei 是 .ttc 集合，Unity 经常静默回退到 Arial（无 CJK 字形）→ TMP 烘焙出的图集不含中文 → 所有中文渲染为方框，且无任何报错。
- 解决：遍历 12 个候选字体，用 `font.HasCharacter('中')` 逐一验证；通过后才创建 TMP 资产（2048² + Dynamic + 多图集）。

### 15. 第三轮：截断/错位根因修复 + 视觉粗糙优化（ui-ux-pro-max skill 指导）
**用户反馈**：UI 仍有错位，上下栏显示不全，整体粗糙。加载 ui-ux-pro-max skill，按「对比度/间距/深度/反馈」四维度优化。

**A. 截断与错位根因（两个独立问题）**
- **CanvasScaler 设置**：`matchWidthOrHeight = 0.5f` → `ScreenMatchMode.Expand`。
  原设置导致画布尺寸随窗口比例漂移（窄屏下宽<1280），内容被推到画布外。
  Expand 保证画布在宽和高两个方向都至少等于参考分辨率（1280×720），几何上不可能裁切。
- **FitContent/FitCardGroup 初始帧错误缩放**：Update 中 `_band.rect.width` 在 Awake 后第一帧常为 0，原代码 `Mathf.Clamp(0/1040, 0.62, 1)=0.62` 把内容层直接缩到 62%，且 Lerp 恢复极慢（肉眼可见的"呼吸"错位）。
  修复：① `if (w <= 1f) return;` 跳过无效帧；② 移除 Lerp，直接设置 scale；③ 最低缩放 0.62→0.72（减少拥挤感）。

**B. 视觉粗糙优化（skill 原则：对比度 4.5:1、统一圆角、深度阴影、微交互反馈）**
- **边框可见度**：SlotEdge α 0.10→0.22；Edge α 0.14→0.26；EdgeStrong α 0.38→0.50。
  原边框几乎透明，面板像浮空色块，没有边界感。
- **投影深度**：新增 `TdTheme.ShadowColor` (black, α0.20) + `ShadowDistance` (0,-3)。
  `CreateButton` 和 `CreateVectorPanel` 自动附加 `Shadow` 组件。
  解决「所有面板贴在一起没有层次」的粗糙感。
- **圆角统一**：按钮从直角 `cornerRadius=0` → `TdTheme.Radius.Sm`（4px），与卡片圆角系统一致。
  解决「直角太硬、与卡片不协调」的粗糙感。
- **按钮交互反馈增强**：highlighted 色从「加 14% 白」改为「加 28% 微蓝」；pressed 从「加 20% 黑」改为「加 38% 深蓝」；disabled 从灰 0.5 改为更暗的灰蓝。
  解决「按钮 hover/press 反馈太弱，像死控件」的粗糙感。
- **进度条边框**：背景 border α 0.12→0.20，边界更清晰。
- **卡片状态反馈增强**：
  - 选中 borderWidth 2.5→3.2，hover 1.8→2.4
  - 选中 glow α 0.32→0.45，hover 0.12→0.20
  - 常规 top-band α 0.32→0.40（未选中时颜色也能看到）
- **顶栏交互反馈**：
  - 速度按钮选中时 borderWidth 从 1.2→2.2
  - 暂停按钮在暂停态边框变红（Barrier 色），提示玩家当前处于暂停

**C. 验证**
- 静态扫描：46 文件括号全平衡，无新增 API 不匹配。
- 结论：本轮修改涉及 UiFactory.cs / HudTopBar.cs / HudDeployBar.cs / TdTheme.cs，均为编译安全范围内的颜色和数值调整。

### 16. 第四轮：布局回退（Expand→match-width）+ 游戏感升级
**用户反馈**：界面元素完全乱了；元素太简单，不像游戏像教学产品。

**A. 布局乱的根因（Expand 是错的）**
- 上一轮把 `CanvasScaler` 改成 `ScreenMatchMode.Expand`。Expand 让画布在两个方向都 >= 参考分辨率，
  在**非 16:9 自由比例**下会把画布拉得比 1280×720 大很多（如宽屏下宽 1707、竖屏下高 1920），
  顶/底栏内容被摊开、元素飘在巨大空白里 → 用户看到的「完全乱了」。
- 修正：`matchWidthOrHeight = 0f`（锁定宽度）。画布宽度永远 = 1280，整体随屏幕宽度等比缩放；
  为 1280 宽设计的顶/底栏布局永远成立，bar 内容不摊开、不裁切，顶栏恒在上缘、底栏恒在下缘。
  （竖屏下中间只是更高的战场区，非缺陷。）

**B. 游戏感升级（ui-ux-pro-max 原则：层次 / 框架 / 史诗感 / 信息密度）**
- **全屏背景景深**：`TerminalHud.BuildBackdrop()` 在最底层加 `SpriteFactory.Vignette`（四角暗角，α0.5）
  + `GradientTop`（上缘深蓝冷光压暗，高 150），让 HUD 浮在战场之上，告别「贴在平面上的教学图」。
  需 `using TowerDefense.Util;`。
- **四角 L 型角标框（仪器截框感）**：`TdKit.Corners` 应用到
  顶栏(Star α0.55, 16/2)、符卡(Star α0.5, 10/1.5)、弹幕环(Spirit α0.5, 12/2)、单位卡(Star α0.5, 12/2)。
  敌影卡本就有四角锁定框（随体伸缩），不再重复。
- **衬线英文卷标**：顶栏 `_roundEng`（WAVE II 类）改用 `UiFont.SerifTmpFont`（Georgia 系）+ `SetCharacterSpacing(2)`，
  立刻跳出教学体、立住幻想/史诗气质。`UiText.SetFont/SetCharacterSpacing` 是 internal，同程序集可调用。
- **符卡快捷键角标徽章**：原左上角纯文字序号改为 Star 蓝小圆角 badge（α0.9, 无边框 borderWidth=0）+ 白字，明显可辨。

**C. 验证**：静态扫描 46 文件括号全平衡；Corners/SerifTmpFont/Vignette/GradientTop 符号均解析。
- 注意：`TdKit.Glass(..., Color.clear, 0f)` 中 edge=Color.clear 等于 default(Color)，会被 Glass 内部重置为 TdTheme.Edge，
  但 borderWidth=0 不渲染，故 badge 实际无边框（符合预期）。

- **编译错误修复（CS0117）**：`HudTopBar.cs` 误写 `UiFont.SerifTmpFont`，但 `SerifTmpFont` 定义在 `UiFactory.cs`
  （不在 `UiFont.cs`）。改为 `UiFactory.SerifTmpFont` 后通过。教训：衬线字体资产在 UiFactory，中文 TMP 资产在 UiFont，别混。

### 17. 第五轮：无头布局校验器定位顶栏真实 bug（不再猜）
**用户反馈**：元素还是乱的（挤在一起/错位）；整个 UI 仍老风格，没有美学重构。

**根因诊断方法升级**：本地无 C# 编译器，前几轮靠读代码猜 bug 屡猜不中。本轮改用**无头布局校验器**
（`.workbuddy-ai/verify_layout.py`）—— 用 Python 复刻 `TdLayout` 的 anchor/pivot/anchoredPosition/sizeDelta
数学，把 `HudTopBar.Build` / `HudDeployBar.Build` 的定位逐行翻译成矩形计算，输出每个元素坐标并自动检测
兄弟元素重叠与越界。这是脱离 Unity 也能确定布局是否正确的唯一可靠办法。

**校验结果（结论性）**：
- **底栏（HudDeployBar）完全正确**：LeftCluster [16,152]、CardGroup [317,963]（5 卡无重叠）、BarrageCluster [1198,1264]
  彼此不重叠，卡片在容器内（所谓 overlap 仅为父子包含，非真实 bug）。
- **顶栏（HudTopBar）有两个真实 bug**：
  1. 幕次模块内容被推到右侧并溢出 150px：模块 300 宽，但 `_roundTitle/_roundEng/_roundBar` 用
     `At(rt, 150, …)` + `width 280`，使内容在模块局部坐标占 [150,430]，标题实际画到画布 x[640,920]，
     撞进 Barrier[882,1006] 与 Enemy[738,870]。
  2. 敌影胶囊与幕次模块重叠 52px：Enemy `InRight(…,410,132)` → 画布 [738,870]，而模块 [490,790]。

**修复（已写入 HudTopBar.cs，校验器复算确认零重叠）**：

  `At(value, 36, 17, w-44, 24)`，三个胶囊（灵力/结界/敌影）的值都不再越界。

### 18. 第六轮：用户认定"仍是老一套/屎山堆屎山" + 预览丑 → 真·美学重构（参照明日方舟）
**用户反馈**："不是我没看见你的修改，而是你的修改根本就是屎山上面堆屎山，而不是重构。我看到的绝大部分还是原来那一套。"
"而且你做的整个预览也很丑。搜一下明日方舟之类的设计好好看看，或者用你的skill。"

**定位（关键认知转折）**：
- 彻底排查：项目里**只有一个 HUD**（`TerminalHud`，由 `GameBootstrap` 运行时自动创建，单 Canvas，无场景 prefab、无第二个 HUD 类）。
  所谓"原来那一套"并非隐藏旧 HUD 仍在渲染，而是**我重构出的"新"系统视觉上仍像旧原型**——扁平暗色矩形 + 弱层级 + 无统一强调色，
  被用户判为"换皮/堆屎山"。`RoundedRectImage.ForceSquareEdges=true` 让所有面板都是直角平块，叠加扁平暗填充 → 教学产品观感。
- 结论：用户要的是**视觉语言的真重构**，不是坐标微调。本轮用 frontend-design skill + 联网研究明日方舟官方 UI 语言后重做。

**明日方舟视觉语言（研究结论，来自官方 wiki CSS + 多篇 UI 分析）**：
- 底色近黑炭灰 `rgb(20,21,22)` 分层叠加出深度，非纯黑非蓝。
- 招牌强调色青蓝 `#22BBFF`（全局唯一活跃色）。
- 直角（`border-radius:0`）+ 发丝描边 `#535353`，活跃态用强调色描边。
- 受微软 Fluent Design 影响（亚克力/深度/描边光）+ Diegetic 全息投影军工科幻感。
- 层级对比度极高是其标志性优点；米哈游系语义配色（每类型=独立色相 + 内部发光）作塔卡参考。

**落地（C# 与 HTML 预览同步）**：

### 20. Unity 首编报错 CS1503 修复（HudTopBar.cs:157）
**报错**：`HudTopBar.cs(157,27): error CS1503: Argument 1: cannot convert from 'TowerDefense.UI.RoundedRectImage' to 'UnityEngine.Transform'`
**根因**：`Cell()` 辅助法里 `var cell = TdKit.Glass(...)` 返回 `RoundedRectImage`（组件），第 157 行却把 `cell` 直接传给 `TdKit.Corners(parent, ...)`，
而 `Corners` 第一个参数是 `Transform`。同级调用（如 156 行 `TdKit.Sheen(cell.transform, ...)`）都用 `.transform`，唯独 Corners 漏了。
**修复**：`TdKit.Corners(cell, ...)` → `TdKit.Corners(cell.transform, ...)`。
**同类排查**：全量 Grep 所有 `TdKit.{Corners|Sheen|AccentLine|Glass|Ring|Glow|Text|Button|Line}` 调用点，确认其余首参要么是 `RectTransform`（NewChild 返回 / 字段声明），
要么带 `.transform`/`.rectTransform`；`HudUnitCard._panel`(RectTransform)、`HudEnemyInspector._lockRoot`(RectTransform) 均正确。确认全代码库仅此一处该错误。
`scan_tokens.py` 复跑：括号全平衡、API 全命中（CreateProgressBar 元组返回误报照旧）。请用户重新编译并粘贴下一个 `error CS`（预期为空）。
