# 2026-09-16

## 灵力（部署费用）累计逻辑重构

需求：灵力初始给一笔、击败不同敌影给不同回复、撤退符卡返还一部分灵力。
澄清结论：本作「灵力」= 金币 = 部署符卡的唯一资源（UI 标签 `灵力 SPIRIT`），
数值手感对齐**明日方舟部署费用（DP）**。左下角那条充能条是「弹幕威力 POWER / P点」，不是灵力。

### 改动
- `GameConfig.cs`
  - 原「经济 / 基地」块重写为「灵力 SPIRIT（部署费用 · 参考明日方舟 DP）」块，
    注释里写明累计逻辑 = 三个进项（初始 / 自然回复 / 击破回复）+ 两个返还口（撤退 / 被击毁）。
  - 新增 `StartingSpirit = 150`（原 `StartingGold = 240`）、`SpiritRegenPerSecond = 1`（原 `PassiveGoldPerSecond`）、
    `MaxSpirit = 1500`（原 `MaxGold`）。
  - `RoundClearGold → RoundClearSpirit`、`AnnihilationMilestoneGold → AnnihilationMilestoneSpirit`、
    `ScorePerGold → ScorePerSpirit`、`PracticeStartingGold(stage) → PracticeStartingSpirit(stage)`
    （= `StartingSpirit + stage*180`，stage4 = 870）。
  - 敌人定义字段 `GoldReward → SpiritReward`，保持按威胁度分级：普通 10 / 高速 12 / 重装 30 / 强敌 100。
- `GameManager.cs`：`_gold → _spirit`、`Gold → Spirit`、`AddGold → AddSpirit`、`TrySpendGold → TrySpendSpirit`；
  `NotifyEnemyKilled(enemy, spirit)`；`RetreatTower` / `OnTowerDefeated` 增加「灵力 +X」世界浮动文字。
- `Enemy.cs`：`_goldReward → _spiritReward`，击破浮动文字改为 `灵力 +N`。
- 引用同步：`TowerPlacer`、`BattleUiRoot(.cs/.Views.cs)`、`HudDeployBar`、`HudTopBar`、`FrontEndUi`、
  `HudEnemyInspector`、`HudFeedback`、`Assets/Editor/MenuFlowVerification.cs`（断言 240→150、960→870）。

### 注意
- 用 Edit 工具**并行**改同一个文件会发生写覆盖，多条改动会静默丢失（部分报 EBUSY）。
  同一文件的多处修改必须逐条串行执行，改完用全局检索复查。
- `BattleUiRoot` 里的私有 UI 字段仍叫 `_gold` / `_lastGold` / `_goldPulse`（纯显示层命名，未改）。

### 校验
- 双向检索：旧符号（`StartingGold / GoldReward / AddGold / game.Gold` 等）零残留；
  新符号（`StartingSpirit / SpiritReward / AddSpirit / game.Spirit` 等）全部有定义且引用一致。
- 新增 `.workbuddy-ai/verify_symbols.py`（花括号配平 + 符号存在性静态校验）：
  1061 条引用、0 配平问题、0 未解析引用，退出码 0。
- **Unity 编译没跑通**（三次尝试）：
  - 不加 `-noUpm` → `[Package Manager] Could not connect to IPC stream`，直接 exit 1；
  - 加 `-noUpm` → 进到 `Application.AssetDatabase Initial Refresh Start` 后卡死，
    17 分钟日志零进展、`Library/ScriptAssemblies/Assembly-CSharp.dll` 时间戳不变；
  - 结论：本机沙箱环境跑不了 Unity batchmode，编译仍需用户开工程确认。
    日志残留在 `Logs/compile-check*.log`。
