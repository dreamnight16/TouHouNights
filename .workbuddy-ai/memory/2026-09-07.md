## UI 架构重构：Flat Spatial 三层结构（依据 new.md）

用户追加要求：*基于 `~/Downloads/new.md` 重构 UI，核心玩法与设定不变*。new.md 的核心是「平面信息 + 空间层次 + 非线性动效」，主张 UI 是一套操作系统（Design System）而不是一堆按钮。

### 结论：重构 3 个文件、新增 6 个文件、删除 1 个单体巨类
- **TerminalHud.cs：1215 行 → 约 90 行**，退化为装配器（AddComponent 各子组件 + 全局快捷键转发 + 结算屏显隐）。
- 新增：`HudTopBar`（①战局状态层）、`HudDeployBar`（③快速操作层）、`HudUnitCard`（贴身单位卡）、`HudEnemyInspector`（悬停敌影卡）、`HudFeedback`（纯反馈层）、`HudRangeIndicator`（几何化攻击范围）、`TdLayout`（布局原语）。
- 改造：`TdTheme` 加 Sem/Space/Motion/Radius 令牌层、布局常量改名 TopBarH/BottomBarH/CardW/CardH/CardGap；`TdKit` 加 SpellOrder/SpellIndex/RoleOf；`TowerPlacer` 删逐格半透明方块池改调 `HudRangeIndicator`；`Enemy` 加只读属性 Definition/Health/MaxHealth/IsBoss/IsSlowed。

### 关键设计决策（下次改 UI 时要守住）
1. **渐进式披露**：部署卡默认只有「职业图标+费用」，名称悬停才淡入；敌人默认只有血条，悬停才展开卡片；单位卡只在选中时存在。
2. **状态可视化 > 数值读数**：弹幕就绪 = P 点环满 + 图标 `P`→`✦`，不写倒计时数字。
3. **信息贴主体**：`TdLayout.BesideUnit()` 统一处理「优先放右侧、右侧放不下翻左侧、夹在 SafeTop/SafeBottom 之间」，配一条旋转引导线连回单位。新增任何贴身面板都用它，别再手写 anchor 数学。
4. **干净几何范围**：整体淡蒙版(α .085) + 四条边界线(α .55) + 四角 L 角标(α .92 呼吸) + 极淡格线(α .14)。固定 13+4N 个对象，不建池。
5. **系统按钮不进战斗 HUD**：「继续/再来一战」下沉到 `HudFeedback` 的暂停覆盖层，只在暂停时出现。
6. **兄弟节点顺序 = 绘制顺序**：HudTop/Deploy/UnitCard/EnemyInspector → HudFeedback（警示要盖住读数）→ TerminalResult（最上）。

### 踩坑记录（本次新增）
- **新组件忘加 `using UnityEngine.UI;`** —— `HudTopBar`（用 `Button`）和 `HudEnemyInspector`（用 `Image`）都漏了，静态审查才发现。凡是新建 UI 组件，先写全 `UnityEngine.UI`。
- **`CanvasGroup.blocksRaycasts = false` 会让整组按钮点不动**：暂停覆盖层必须按 alpha 动态切换 `blocksRaycasts/interactable`，否则「继续/再来一战」永远点不到。
- **透视相机下拾取敌人要用敌人自身的高度平面**：`new Plane(Vector3.forward, new Vector3(0,0,GameConfig.EnemyVisualHeight))`，用地面 z=0 平面会因视觉高度产生偏移。
- **不要相信 `SpriteFactory` 的缓存粒度**：`RoundedSquare` 按 size 缓存 512² 贴图，变尺寸会各建 1MB；需要缩放的图元一律用 `Square(1f, Color.white)` + `localScale` + `SpriteRenderer.color` 染色。
- 本机没有可用 C# 编译器（csc 被安全策略拦截，Unity Editor 未运行），**只能靠静态审查**：建议流程 = ① Python 脚本全量括号配平 ② 正则抽取 `TdTheme./TdKit./TdLayout./UiFactory.` 引用与定义比对 ③ Explore agent 做语义级交叉检查。本次靠这三步抓出 2 处编译错误。

## 世界层视觉重构（WorldArt 设计系统）

需求：上下操作台显示不全 + 地图/塔/敌人「像学生玩具」，只保留核心玩法做完全重构；配色否决 Terminal Green，改走明日方舟方向（清新但不失科技感）。

### 布局 BUG（已修）
- 根因是 CanvasScaler matchWidthOrHeight=0.5，实际画布宽度会偏离 1280 参考分辨率，**写死 x 坐标必然翻车**。
- BottomBarH 84→104，新增 TdTheme.BottomAxisY=60 作为底栏唯一基线，所有底栏子元素对齐到它（弹幕按钮 58 高、辉光 80 高都居中于 60，下缘 31/20）。
- 新增 TdLayout.AtMidTop / AtMidBottom（相对父节点水平中心定位），顶栏 SpiritGroup/BarrierGroup、底栏卡片行改用它，彻底去掉 572/588/860/876 等魔法数字。

### 世界层设计系统
- 新增 Core/WorldArt.cs：明度阶梯（4%→8%→12%→18%→30%→55~85%）、统一 1.16× 近黑描边、左上 45° 统一打光、阵营色（天蓝我方 / 珊瑚红敌方 / 琥珀点缀）、Layer* 渲染层序分区。
- SpriteFactory 新增 Hex / Diamond / Arrow / Cross / Corner 图元（含 HexDistance SDF）。形状即信息：六边形=平台，箭形=机动，菱形=精准，圆环=范围，L角标=取景。
- MapSystem 视觉半重写：连续路面（非逐格方砖）+ 方向箭头 + 四角准星 + 自转基地环；玩法半（道路格集合、BFS 距离场、所有 public 查询）原样保留。
- Tower / Enemy / Projectile：三层剪影（描边/本体/顶部受光复用同一贴图）+ 职业与分型专属剪影 + 朝向旋转。

### 踩过的坑
- **并行 Edit 同一文件会丢更新**：两条 Edit 同时改 Tower.cs 时后写的覆盖先写的，导致 _barrel 声明残留（CS0414）。同文件多处修改必须串行。
- **SpriteRenderer 挂在根节点时，设 localPosition 等于移动整个单位**：Enemy 的落地辉光必须单独建子节点，否则所有敌人被拉到父节点原点。
- **SpriteFactory.Corner 的臂厚只有请求值的一半**：区间应为 [0, 2t]，即 Mathf.Abs(a - t) - t。
- **iq 的六边形 SDF 是「平顶」**（顶点在左右、上下是平边），交换 x/y 才是尖顶。子代理审计给过相反结论，是自己验算后否掉的 —— 子代理结论必须复核。
- 四角 L 准星旋转：LB=0 / RB=+90 / RT=180 / LT=-90；且 Corner 贴图的直角顶点在左下角而 pivot 在中心，必须用 R*(o,o) 补偿偏移，直角才落在棋盘角上。
- 本机无 C# 编译器，验证流程 = Python 括号配平全量扫描 + 正则抽取令牌引用与定义比对 + Explore 子代理语义交叉检查。
